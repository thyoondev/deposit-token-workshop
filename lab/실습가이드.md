# 시간표별 실습 가이드

## 10:00~10:30 · 준비

발표자료 3~12페이지에 맞춰 프로젝트를 연다. `npm ci`와 `npm run build`가 성공하는지 확인하고 오류가 발생하면 명령, Node.js 버전, 작업 폴더를 기록한다. 화면에 표시하는 100 WDT와 최소 단위 정수 100은 다르다. 수량은 `ethers.parseUnits("100", 18)`로 변환한다.

완성 예제를 먼저 별도 폴더에 복사해 보관한다. 직접 작성할 때에는 아래 함수의 본문을 읽지 않고 다시 작성한 뒤, 기대 결과와 완성 예제를 비교한다. 전체 코드에는 이후 세션의 통제가 포함돼 있으므로 중간 단계에서 전체 테스트가 모두 통과할 필요는 없다. 복구가 필요하면 보관한 완성 파일로 돌아간다.

## 테스트 작성 양식

각 테스트에 아래 내용을 남긴다.

1. 어떤 정책을 검증하는지 한 문장으로 적는다.
2. 호출자, KYC 상태, 역할, 잔액과 allowance를 준비한다.
3. 동작 하나를 실행한다.
4. 성공하면 상태와 이벤트를 확인한다. 실패하면 오류 종류와 인수, 보존할 상태를 확인한다.
5. 제한 해제가 가능한 기능은 정상 복귀도 확인한다.

## 자주 발생하는 오류

| 증상 | 점검 내용 |
|---|---|
| 모듈을 찾지 못한다. | lab 폴더에서 npm ci를 실행했는지 확인한다. |
| Node 버전 오류가 발생한다. | node --version이 22.13.0 이상인지 확인한다. |
| 컴파일러 다운로드가 실패한다. | 네트워크와 프록시 설정을 확인하고 Hardhat 명령을 하나씩 실행한다. |
| AccessControlUnauthorizedAccount가 발생한다. | connect한 계정과 필요한 역할을 확인한다. |
| KYCRequired가 발생한다. | 오류 인수의 주소가 송신자·수신자·spender 중 누구인지 확인한다. |
| ERC20InsufficientAllowance가 발생한다. | 소유자가 실제 호출자에게 approve했는지 확인한다. |
| EnforcedPause 또는 AccountFrozen이 발생한다. | 현재 정책 상태와 해제 권한을 확인한다. |
| InvalidInitialization이 발생한다. | 이미 초기화한 프록시 또는 잠긴 구현 주소를 호출했는지 확인한다. |
| 업그레이드 검증이 실패한다. | 저장소 배치와 초기화, 상속 변경을 검토한다. 검사를 우회해 통과시키지 않는다. |
